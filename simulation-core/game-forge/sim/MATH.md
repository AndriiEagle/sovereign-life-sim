# Математическая модель жизни, v1

Это самостоятельная игровая модель S1/S2/S3/S4/S12, а не медицинский,
психологический или финансовый прогноз. Числа прежнего Godot-прототипа
по фазам не заменены: его код и данные не менялись. Здесь новая дискретизация
для будущего порта. Решения Андрия о погоде, свете, привычках и деньгах сохранены.
Все настраиваемые числа лежат в `params.json`, вместе с единицей, допустимым
коридором и ключом источника. Числа 0/1 в формулах — границы нормировки и
математические тождества. Имена полей, типы действий и порядок расчёта — контракт.

## Обозначения и время S1

`clip(x)=min(1,max(0,x))`, шаг `Δt=15/60=0.25 h`.
`k` — целое число завершённых шагов, `D=24*60/15=96` шагов/сутки.

```
k' = k+1
day(k) = floor(k/D)+1
hour(k) = (k mod D)*15/60
week(k) = floor(floor(k/D)/days_per_week)+1
season(k) = seasons[floor(floor(k/D)/days_per_season) mod len(seasons)]
```

День 1 начинается в полночь. Четыре фазы: ночь 00–06, утро 06–12,
день 12–18, вечер 18–24. Фаза выбирается по порогам `clock.phases`.
Сезон длится 21 игровой день: четыре сезона дают 12 недель из черновика S1.
Это игровое сжатие времени, не реальный календарь Цюриха.
Состояние дня `weather` задаётся извне: при создании состояния или действием
на границе суток. В середине суток смена погоды отвергается.

## Состояние, единицы и диапазоны

| Поле | Единица / диапазон | Смысл |
|---|---|---|
| `energy E`, `burnout B`, `mood M` | доля `[0,1]` | Нормированные шкалы |
| `habits[h] H` | автоматизм `[0,1]` | Не моральная оценка поведения |
| `habit_dose[h] d` | суточные повторения `[0,1]` | Защита от фарма привычки |
| `habit_streak[h]` | целые сутки `>=0` | Последовательные полные дозы |
| `practice_hours[j] P` | эффективные часы `>=0` | Накопленная практика |
| `skill_value(P)` | доля `[0,1)` | Производительность навыка |
| `skill_level` | целое `0..5` | Проекция по порогам в данных |
| `balance_cents`, `net_cents` | целые раппены | Баланс и сумма принятых транзакций |
| `pending_energy`, `pending_burnout` | доли шкал, знаковые | Эффекты ближайшего утра |
| `tick` | целое `>=0` | Источник календаря |
| `rng` | `uint32` | Состояние переносимого генератора |
| `transactions`, `events` | списки | Только результат последнего шага |

Для существующего UI: энергия/выгорание = `100*E`, `100*B`;
настроение = `10*M-5`. Старт `E=.55`, `B=.40`, `M=.5`.
Накопители часов, время и деньги не ограничиваются `[0,1]`.

## Погода и вечерний свет

У состояния дня два коэффициента: `w_E`, `w_M`.
В исходных данных золотая осень: `(+.10,+.20)`, серый дождь: `(-.10,-.20)`,
нейтральный день: `(0,0)`. Для включённого света с 18 до 24 часов:

```
c = light.negative_weather_compensation     # .5
w_eff = w*(1-c) if w<0 else w
```

Вне окна или при выключенном свете `w_eff=w`. Свет частично убирает
отрицательный погодный вклад, не превращает дождь в солнце.
Солнечная погода не увеличивает предельное восстановление во сне.
Это изменение целевого уровня, а не бесконечная прибавка за каждый тик.

Научный ориентир: Rosenthal et al. (1984), *Seasonal affective disorder:
A description of the syndrome and preliminary findings with light therapy*,
Archives of General Psychiatry 41:72–80. Связь сезонного света и настроения
реальна как тема исследования; конкретные величины здесь придуманы для игры.
Уличное свет-сопровождение не приравнивается к клинической светотерапии.
Немедленный эффект одного дождливого дня не выведен из исследования SAD.

## Энергия S2: устойчивая релаксация

Для выполненного действия `a`, прежнего `B` и текущей погоды:

```
T = actions[a].energy_target                         # во сне
T = clip(actions[a].energy_target + w_E_eff - β_E*B)  # в бодрствовании
λ = sleep_rate_per_hour * sleep_quality              # во сне
λ = awake_rate_per_hour                              # в бодрствовании
E' = T + (E-T)*exp(-λ*Δt)
```

`λ` измеряется в `h^-1`, `β_E` — доля шкалы. При `λ>=0` шаг — выпуклая
комбинация `E` и `T`, поэтому без отсечения сохраняет границы.
Больше качества сна увеличивает энергию при том же исходном состоянии;
добавление сна вместо отдыха также проверяется на полных шагах.
Это утверждение при прочих равных, не сравнение произвольных расписаний
с разными алкоголем, расходами и утренними эффектами.

При **фиксированных** действии, погоде, свете, качестве и выгорании:

```
E_n = T + (E_0-T)*exp(-λ*Δt*n),   E_equilibrium=T (если λ>0)
```

При `λ=0` энергия постоянна; единственного равновесия нет.
Тест сравнивает независимую замкнутую формулу с итерацией и 10 000 шагов
с `T`; максимальная допустимая абсолютная ошибка `1e-9`.
Это равновесие подсистемы, не всей жизни с меняющимся выгоранием.

Ориентир: Borbely (1982), *A two process model of sleep regulation*.
Взята идея насыщаемого восстановления. Циркадный процесс и биология сна
не воспроизведены; параметры — игровая калибровка, не эмпирическая оценка.

## Выгорание S2: медленное накопление перегруза

```
L = clip(action.load + low_energy_load * I(E<low_energy_threshold and awake))
B' = clip(B + Δt*(accumulation_per_hour*L - recovery_per_hour*action.recovery*B))
```

Затем применяются непосредственные эффекты привычки и, на границе утра,
накопленные отложенные эффекты. `L` и `recovery` в `[0,1]`, накопление
`.005..009` доли/час, восстановление `.003..007 h^-1`. Сон восстанавливает
медленно относительно энергии. Работа при низкой энергии усиливает нагрузку.

От начального `B<=.4` в первый день даже верхняя оценка
`.4 + 24*.009 + .05 = .666 < .7`: непрерывная максимальная нагрузка плюс
максимальная одна утренняя алкогольная доза не достигают минимального порога.
Это **не** обещание для загруженного состояния `B=.699` или произвольного
внешнего `pending_burnout`: такое состояние может пересечь порог за шаг.

Определённый тестовый перегруз: каждый день 8 часов сна и 16 часов обычной
работы, нейтральная погода, без привычек с утренними эффектами.
Для всех 16 углов коридоров `B0 in {0,.4}`, накопления, восстановления и
порога `.7..8` пересечение наступает не позднее `overload_max_days=30`.
Другие расписания не имеют универсальной гарантии достижения выгорания.
Сложные задачи при пороге закрываются; базовая работа остаётся доступной.

Источник формы: Maslach, Schaufeli & Leiter (2001), *Job Burnout*, Annual
Review of Psychology 52:397–422: хроническая перегрузка, а не мгновенный
урон. Уравнение, длительность и пороги — авторская игровая модель.

## Настроение

```
U = clip(action.mood_target + w_M_eff - β_M*B)
M' = U + (M-U)*exp(-mood.rate_per_hour*Δt)
```

Вход — прежний `B`. Алкоголь/экран могут дать краткое облегчение без
морализаторства; настроение не используется как диагноз. Оно не дублирует
энергию и не меняет её скрытыми коэффициентами.

## Привычки S3

Для каждой привычки есть `dose_hours`, порог суточного полного повторения.

```
δ = min(1-d, Δt/dose_hours)  # только для реально выполненного действия
d' = d+δ
α = 1-(1-q)^(1/T95),  q=.95, T95=66 дней
H' = 1-(1-H)*(1-α)^δ
H_n = 1-(1-H0)*(1-α)^n
```

При ежедневной полной дозе `H_66=.95` от нулевого старта. `T95` допускает
18–254 дней. Десять часов одного поведения не дают десять суточных повторений.
В полночь `d=0`; полный день повышает streak, неполный обнуляет streak,
но **не** накопленный автоматизм. Ярлык появляется после трёх полных дней.
Медиана не означает, что любая привычка у любого человека формируется за 66 дней.

Ориентир: Lally et al. (2010), *How are habits formed: Modelling habit
formation in the real world*, EJSP 40:998–1009, DOI `10.1002/ejsp.674`.
66 и 18–254 переданы пользователем; асимптотическая форма и критерий 95%
использованы для игровой калибровки. Источник не перепроверялся по сети.
Дозы часов и правило ярлыка из S3 — дизайн, не результат Lally.

Эффекты на одну полную дозу, из данных S3:

| Действие | Сейчас | В ближайшее 06:00 |
|---|---|---|
| Алкоголь | повышенный mood target; `B += -.03*δ` | `E += -.20*δ`, `B += .05*δ` |
| Сериал | повышенный mood target | `E += -.05*δ` |
| Спорт | пониженный energy target | `E += .10*δ`, `B += -.03*δ` |
| Сон | насыщаемое восстановление | отдельной двойной награды энергии нет |
| Своя игра | расход энергии, практика кода, высокий mood target | отдельного эффекта нет |

Отложенные эффекты накапливаются, применяются один раз и обнуляются.
Эффект действия на интервале 05:45–06:00 уже входит в это утро.
В течение дня можно получить несколько разных привычек; их эффекты суммируются.
Прогресс игры-мечты S10 не входит в это ядро; практика кода не подменяет релиз.

## Навыки S4

```
P_j' = P_j + Δt*E*(1-B)        # только у выбранного навыка выполненной практики
S_j(P) = 1-(1+P/τ)^(-γ)
level = max index i with S>=level_thresholds[i]
```

`τ=20` эффективных часов, `γ=.6`, уровни `0..5`. Производная положительна,
вторая отрицательна: убывающая отдача без мгновенного достижения мастерства.
Количество навыков, разрешённые действиям цели и пороги лежат в данных.
Учёба позволяет выбрать немецкий, контекст, код, электронику, общение,
тело или фокус. Сон **не** начисляет практику. Практика не забывается в v1.

Ориентир: Newell & Rosenbloom (1981), *Mechanisms of skill acquisition and
the law of practice*. Здесь степенной закон остаточной ошибки преобразован
в нормированный навык. Конкретные коэффициенты, уровни и связь с энергией
авторские. Начальные часы нулевые: перенос B1/переводов из действующей
языковой механики требует отдельной калибровки и не выполнен этим модулем.

## Деньги S12

```
C' = C + Σ accepted_transaction.amount_cents
net' = net + Σ accepted_transaction.amount_cents
C = initial.balance_cents + net
```

Только целые раппены, без float и округления. Сначала стоимость действия,
затем его заработок, внешние переводы в порядке списка. На завершении суток
приходит месячная помощь (если кратно периоду), затем списывается дневной быт.
Первый платёж помощи — на завершении 30-го дня; стартовый баланс отдельный.
Шаг 2880 завершает 30 дней, его транзакции входят в CSV.

Расход, создающий/увеличивающий отрицательный баланс, отклоняется, если
нет явного `allow_debt=true`. При разрешении долга каждое его увеличение
создаёт событие `debt` с точной суммой. Оплата недоступного действия не берётся,
неоплаченное платное действие заменяется отдыхом. Неоплаченный быт выдаёт
`insufficient_funds`; задолженность по счетам не моделируется автоматически.
Внешние переводы выполняются даже при блокировке основного действия.
ID транзакции — подпись, не глобальный ключ идемпотентности.

Суммы зарплат, помощи и быта — игровые значения. Источник — требования S12
и решение P6 о ранних деньгах, не реальные нормы соцпомощи/зарплаты Швейцарии.

## Решения, случайность, порядок шага

Все числовые пороги и вероятности решений хранятся в данных:

```
r' = (1664525*r + 1013904223) mod 2^32
u = r'/2^32
p_failure = clip(action.failure_base + action.failure_burnout_factor*B)
```

LCG используется ради точного переноса на GDScript (`int64` промежуточное
произведение безопасно для этих констант). Один draw за каждый шаг, включая
заблокированные действия. Приоритет отказов: энергия ниже минимума →
порог выгорания для закрываемых задач → `u<p_failure` → нехватка оплаты.
Отказ возвращает событие с причиной и выполняет отдых, время идёт.
Это явный игровой контракт, а не молчаливый отказ.

Порядок: валидация → draw → суточная погода → проверка/оплата действия →
заработок и внешние переводы → энергия/выгорание/настроение по старому состоянию
→ доза привычки и практика → время +1 → утренние эффекты → суточные деньги
и streak. Применение эффектов и состояние RNG полностью входят в экспорт.
Ни исходное состояние, ни action, ни params не мутируются.

## Проверки и предел доказательства

`unittest`: замкнутая привычка против итерации; аналитическая энергия против
10 000 шагов; производные навыка; 10 000 сценариев с независимым seed и
1–24 шагами, повторное проигрывание, границы/конечность, точные транзакции;
дополнительные длинные перегрузы и три 30-дневных расписания.
Случайная выборка не является доказательством всех возможных входов.

Дистанция архетипов — RMS по всем тикам и восьми координатам:
энергия, выгорание, пять привычек, `balance_cents/distance_scale_cents`.
Порог `.08` из данных. Отдельно тот же тест обнуляет денежную координату:
одна зарплата не может замаскировать одинаковые жизненные траектории.

Мутация заменяет знак затухания энергии на рост **в изолированной копии**.
Тот же аналитический oracle обязан пройти на оригинале и упасть через
`AssertionError: ... ENERGY_DECAY_ORACLE` на копии. Лог привязан к хешам
ядра, параметров и теста. Python-векторы задают эталон будущего порта;
работающий GDScript-порт и пользовательское принятие баланса не заявляются.
